# Wardrobe editor design and delivery plan

**Status** · Proposed design for review

The wardrobe planner runs by opening `cabinet-plan/index.html`. It uses plain JavaScript, SVG drawings, a local browser draft, and JSON import and export. Keep that offline workflow. The current model has two independently saved presets, fixed overall dimensions, one optional partial-depth side notch, and a print preview with front, side, and isometric views. The existing Node model suite passes all seven tests.

## Design choices

| Approach | Trade-off |
| --- | --- |
| Extend the current notch fields | Fast for a few preset shapes. Multiple recesses, projections, and radii would require duplicating validation and drawing rules. |
| **Recommended · Edit the outline with dimensioned cuts and extensions** | Drag handles for rough edits and enter exact millimetres in the inspector. One geometry model drives preview, validation, snapping, and print. Keeps the project offline. |
| Build a general 3D solid editor | Supports freeform surfaces and arbitrary angles. Requires a larger editor, geometry engine, and file format than the wardrobe workflow calls for. |

The proposed outline tools create connected, right-angled cabinet shapes with individually rounded inside and outside corners. Features can be placed on any edge of the front profile and assigned a depth range. This covers multiple side recesses, overhead extensions, and partial-depth shapes in the same layout. Freehand outlines, angled walls, and curved surfaces in arbitrary planes would require a further design decision.

## Measurements and print

- Add a **Full measurements** toggle on the drawing toolbar. The default compact view shows overall dimensions and bay widths. Full view adds feature dimensions and positions, inside opening sizes, corner radii, and part sizes and coordinates. Show front-view X/Y dimensions, side-view Y/Z dimensions, and use isometric for context. Identify dense or coincident features with numbered callouts and a keyed table so their dimensions remain readable in the drawing and in print.
- Give **Print drawings** a **Full measurements** option that initially matches the editor. Changing it updates the preview and the system print output together. Route browser-initiated printing through the same renderer. In full mode, let dimensioned elevations use their own pages when needed. Verify labels, extensions, and radius callouts at the page edges on A4 and Letter. Keep handles, selection state, and snap guides out of the printed SVG.
- Cover both meanings of moving cabinet dimensions. A **Cabinet dimensions** inspector sets the nominal width, height, and depth in millimetres. Drag the overall dimension lines independently to move their callouts, or use numeric offset fields and **Reset position**. A resize keeps the bottom-left-front datum fixed, preserves explicit part coordinates, and re-evaluates auto spans and the rack mount. If a resize would invalidate a bay, feature, or part, identify it in the inspector and leave the last valid layout in place.
- Show nominal dimensions in the inspector and actual overall extents on drawings when an extension projects beyond the nominal envelope. Keep the original coordinate datum for existing plans even if a new extension extends to negative X or Y.

## Column count and history

- Keep the existing three- and four-column presets as independently editable layouts. Add an integer column-count field and create an independently named custom layout from the current layout. A new blank partition starts with near-equal whole-millimetre widths. At 1821 mm the range is 1–18. In general it is 1 through `floor(nominalWidth / 100)`.
- In an occupied layout, let users preview new divider positions and review which parts and bay assignments would be affected. Preserve exact positions and place a part in a new bay if it fits wholly in that bay. If explicit spans cross a proposed divider or an anchored shelf or rail would change span, identify the affected parts and let the user adjust the partition or explicitly accept the new span where it fits. Preserve the source layout and its metadata. Apply a valid partition as one history entry.
- Enforce **at least 100 mm of clear column width** when creating or changing partitions, dragging a main divider, or resizing the nominal cabinet. Validate the first, last, and intermediate bays. Measure the clear width between the nominal side walls and divider positions in this schematic editor. Local contour openings can narrow or interrupt usable space, and their actual clearances should be called out separately.
- Keep existing valid version-1 plans readable, including narrow bays allowed by the old rules. Flag those bays and allow unrelated edits and round trips. Require the 100 mm rule when changing their partition or cabinet width. Preserve both original presets and migrate existing side notches with their original side, position, dimensions, and depth.
- Provide toolbar **Undo** and **Redo** plus Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl+Y. Give focused form controls their normal editing shortcuts. Save one history entry per successful Apply, add/remove, column change, import, callout move, or completed drag. A drag preview, cancelled/invalid edit, or return to the starting position creates no entry. Clear redo after a new committed edit. Keep history for the current session and save the restored plan when undo or redo is used. Leave view changes and pull-out travel previews as view controls.

## Cabinet outline and radii

- Add an **Outline** editor with **Cut in**, **Extend out**, and **Round corner** actions. A feature has a stable ID, an edge and span, a signed perpendicular offset, and front and back Z coordinates. Drag the edge and span handles or enter those values in the inspector. Allow multiple features on the same or different edges, including a feature on a previously created edge. Preview the resulting outline before applying a change. List features so any can be selected, revised, or removed.
- Starting from the nominal rectangle, apply the feature edits in order across the Z intervals defined by their boundaries. Use the resulting boundary geometry for the front projection, left/right side elevations, and isometric view. Render interior depth changes with visible or hidden edges as appropriate. Use the same geometry to determine usable volume, main-divider coverage, part placement, and eligible wall contacts. An extension belongs to the bay attached to that edge and can receive parts over its usable depth. A part with automatic endpoints uses the contiguous supported span at its own Y and across its Z footprint.
- Give each eligible corner a radius field in millimetres. Zero keeps it square. Use a true tangent quarter-circle on straight right-angle edges, for both re-entrant and external corners. Apply each radius through the Z interval over which that corner exists. Derive the largest radius from adjacent straight edge lengths and their neighbouring radii. Reject intersections, overlapping fillets, detached additions, and cuts that leave no valid cabinet in the affected region. Reject an outline change that intersects a placed part and identify that part. Permit exact boundary contact.
- Treat the outline as geometric clearance for the existing schematic parts. Keep curved dimension labels tied to the underlying radius even when isometric rendering needs a linear approximation. A local cut plans the cabinet envelope. Assembly details, panel thickness, and hardware tolerances belong to a fabrication follow-up.

## Part movement, snapping, and pointer

- In the front view, clicking a pull-out rack or short divider shows a small X/Y handle. Dragging its body moves it in both axes. Dragging the X arrow changes only X and dragging the Y arrow changes only Y. Move both Y endpoints of a short divider together to preserve its length. Preserve rack extension travel along Z as a separate control. Main dividers remain full-height bay boundaries that move in X. Use a short divider for a part that can move in Y.
- Use the exact-position inspector as the keyboard and touch fallback, with a visible focus state on the available controls. Keep the same drag projection throughout each gesture so the drawing does not jump as its view bounds change. Release settles on the last valid preview. Escape or pointer cancellation restores the starting state, including the original callout positions.
- Add **Snap while dragging**, off by default. With snapping enabled, pull-out rack edges can meet the closest eligible cabinet wall or main divider. Shelves and clothes rails can align their height to a neighbouring shelf's surface, rail's centreline, or rack sleeve's top or bottom. Candidates must be close to the proposed position in screen space, respect any locked axis, share a relevant span or adjacent bay, and pass the same geometry checks as ordinary movement. Start with a 10 CSS-pixel threshold, break ties by target ID and then by edge order, and show a guide while snapped. Continue free movement if none qualifies. Numeric Apply remains exact.
- A custom pointer is feasible. Offer a small, high-contrast crosshair for the editing canvas, with standard browser cursors as fallbacks and conventional move or resize cursors on handles. Package the cursor as a local asset to preserve offline use. Keep the system pointer for menus, text input, and touch or pen use.

## Additional features worth considering

1. **Clearance overlay.** Show the rack's clearance through its full travel and highlight where a contour or shelf interferes. This is the highest-value follow-up because it makes a shaped cabinet easier to check before sharing the drawings.
2. **Named layout copies.** Duplicate, rename, and compare named alternatives so a user can try two outlines with the same column count.
3. **Fabrication schedule.** Add a labelled parts list once panel thickness, allowances, and joinery are part of the model.

Finish by opening `index.html` directly from disk, importing a version-1 file, editing and printing its migrated layout, exporting and reopening the result, and checking that the other layout is still intact.
